# 레시피 작성 규칙

레시피는 `recipes/<유형>/<번호>-<이름>/` 아래에 둡니다. 유형은 현재 `image`와 `video`를 사용합니다. 번호는 유형별 두 자리 순번, 이름은 모델과 목적이 드러나는 소문자 kebab-case로 정합니다.

## 필수 README 항목

1. 한 문장으로 설명한 목표
2. 확인한 GPU와 소프트웨어 환경
3. 모델·가중치·출력물의 라이선스와 지역 제한
4. 가장 짧은 설치·실행 순서
5. 입력 크기, 프레임 수, 스텝 수 등 재현 설정
6. 워밍업 여부와 측정 시작·종료 지점
7. 실행 횟수와 중앙값 또는 개별 측정값
8. 결과를 넓게 해석하면 안 되는 범위
9. 정적 검사 또는 최소 실행 검증 명령

## 권장 디렉터리

```text
recipe-name/
├── README.md
├── workflows/       # ComfyUI UI/API 워크플로 등
├── scripts/         # 설치, 다운로드, 점검, 측정
├── custom_nodes/    # 레시피에 필요한 최소 커스텀 노드
├── tests/           # 파일 구성과 설정을 확인하는 테스트
└── requirements.txt
```

사용하지 않는 디렉터리는 만들지 않습니다. 설치 스크립트는 레시피 디렉터리를 기준으로 경로를 계산하고, 저장소 루트에서 실행한다고 가정하지 않습니다.

## 저장소에 넣지 않는 것

- 모델 가중치와 체크포인트
- API 키, 토큰, SSH 키와 `.env`
- 서명된 다운로드 URL
- 대용량 생성 결과와 벤치마크 출력 전체
- 공개할 필요가 없는 Pod·Endpoint·Volume 식별자

작은 미리보기는 재현 결과를 이해하는 데 필요할 때만 추가합니다. 원본 결과는 릴리스 자산이나 별도 콘텐츠 저장소를 사용하고 README에는 출처와 생성 조건을 적습니다.

## 결과 표기

속도 수치에는 최소한 GPU, 출력 크기, 프레임 수 또는 이미지 수, 스텝 수, 실행 횟수, 워밍업 여부와 측정 구간을 붙입니다. 한 번만 실행한 값은 중앙값처럼 표현하지 않습니다. 인코딩·파일 저장·네트워크 전송이 포함됐는지도 구분합니다.
